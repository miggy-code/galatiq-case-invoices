# Row-grounded extraction: recorded-response evaluation

Date: 2026-11-07. Model: DeepSeek `deepseek-flash`, with thinking mode disabled
for extraction. The supplied 20-document batch and 12 authored text documents
were scored against the labels in `evals/`.
The outputs in this directory were generated by offline replay of newly recorded
responses after deterministic grounding and format-handling fixes.

| Dataset | Decision matches | False approvals | Per-field groups matched |
| --- | ---: | ---: | --- |
| Supplied batch | 20/20 | 0 | each 20/20 |
| Authored text | 12/12 | 0 | each 12/12 |

The old output had 23 of 38 selected quantity spans contained in header-field
spans. The new output has zero containment or token-boundary violations across
40 selected quantity spans. Ambiguous numeric spans are left unselected and held.

Remaining ungrounded findings:

- `invoice_1002.txt`: held; the model produced a line amount that is absent from
  its quoted row. The invoice also exceeds stock and the high-value threshold.
- `06-unknown.txt`: held; the model assigned the same single `$10.00` token to
  both unit price and line amount. Both evidence entries are ambiguous; the item
  is also unknown.
- `09-missing_due.txt`: rejected; the source has no due date to ground.

Some first recording attempts exhausted their output budget before producing
JSON. They were retried; DeepSeek extraction was then configured with thinking
mode disabled and the prompt was re-recorded. A multi-line row quote on the
rush-delivery example was repaired with one additional recorded model call.
Screening reuses its unchanged existing recordings. The final replay uses the
recordings in `evals/recordings/` and has no network access.

```sh
LLM_MODEL=deepseek-flash LLM_BASE_URL=https://api.deepseek.com uv run python main.py --batch data/invoices --offline --out /tmp/invoices-supplied.jsonl
LLM_MODEL=deepseek-flash LLM_BASE_URL=https://api.deepseek.com uv run python main.py --batch evals/text-invoices --offline --out /tmp/invoices-text.jsonl
uv run python -m invoice_workflow.evaluate --results /tmp/invoices-text.jsonl --labels evals/expected-text.json
```

The supplied score uses batch labels; `python -m invoice_workflow.evaluate` runs the
separate deterministic baseline. See the `evidence_span_issues` check and
`test_recorded_line_evidence_never_overlaps_or_splits_tokens` for span checks.
